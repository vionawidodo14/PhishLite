<h2>What is DMARC?</h2>
<p>DMARC, which stands for “Domain-based Message Authentication, Reporting &amp; Conformance”, is an <a href="/wiki/Glossary#Email_Authentication">email authentication</a>, policy, and reporting protocol. It builds on the widely deployed <a href="/wiki/Glossary#SPF">SPF</a> and <a href="/wiki/Glossary#DKIM">DKIM</a> protocols, adding linkage to the author (“From:”) domain name, published policies for recipient handling of authentication failures, and reporting from receivers to senders, to improve and monitor protection of the domain from fraudulent email.</p>
<h2>Overview of DMARC</h2>
<p>An overview of how DMARC works is available <a href="https://dmarc.org/overview/">on this page</a>.</p>
<h2>Status of DMARC</h2>
<p>The IETF RFC Editor published RFC 7489, “Domain-based Message Authentication, Reporting, and Conformance (DMARC)” on the Independent Submission stream on March 18th, 2015. RFC 7489, which can be <a href="http://tools.ietf.org/html/rfc7489">found here</a>, is in the process of being adopted as the official input to the <a href="https://datatracker.ietf.org/wg/dmarc/">IETF DMARC Working Group</a>.</p>
<p><a name="whyisDMARCimportant"></a></p>
<h3>Why is DMARC Important?</h3>
<p>A brief answer to this question is available <a href="https://dmarc.org/wiki/FAQ#Why_is_DMARC_important.3F">here</a>.</p>
<p><a name="howdoesDMARCwork"></a></p>
<h3>How Does DMARC Work?</h3>
<p>A brief, non-technical answer to this question is available <a href="https://dmarc.org/wiki/FAQ#How_does_DMARC_work.2C_briefly.2C_and_in_non-technical_terms.3F">here</a>. A more detailed explanation is available <a href="https://dmarc.org/overview/">on this page</a>.</p>
<p><a name="whocanuseDMARC"></a></p>
<h3>Who Can Use DMARC?</h3>
<p>DMARC policies are published in the public Domain Name System (DNS), and available to everyone. Because the specification is available with no licensing or similar restriction, any interested party is free to implement it.</p>
