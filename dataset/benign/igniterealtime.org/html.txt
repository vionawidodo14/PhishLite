<div class="ignite_blog_entry ignite_blog_entry_odd"><div class="ignite_blog_entry_header"><img alt="Guus der Kinderen" height="32" src="https://discourse.igniterealtime.org/user_avatar/discourse.igniterealtime.org/guus/32/5664_2.png" width="32"/><div class="ignite_blog_entry_comments"><a href="https://discourse.igniterealtime.org/t/new-feature-using-windows-certificate-stores-in-openfire">1</a></div><h2><a href="https://discourse.igniterealtime.org/t/new-feature-using-windows-certificate-stores-in-openfire" title="New feature: Using Windows certificate stores in Openfire!">New feature: Using Windows certificate stores in Openfire!</a></h2><span class="ignite_blog_entry_author">
                Posted by <a href="https://discourse.igniterealtime.org/u/guus">Guus der Kinderen</a></span><span class="ignite_blog_entry_date">1 month, 43 minutes ago</span></div><div class="ignite_blog_entry_body">
<p>Openfire 4.4.2 brings a <a href="https://issues.igniterealtime.org/browse/OF-1854" rel="nofollow noopener">change</a> that can be leveraged for a new kind of integration with Microsoft Windows.</p>
<p><img alt="tls" data-base62-sha1="jSGJ3oUFkA7kUd0fhbeCwHj9sV1" height="121" src="https://discourse.igniterealtime.org/uploads/default/original/2X/8/8b57ea6499838a51f67cf89cb4b422222f5125c7.png" width="135"/></p>
<p>Traditionally, Openfire ships with its own set of certificate stores. These are the repositories that hold various certificates, which are most commonly used to establish encrypted connections.</p>
<p>As of Openfire 4.4.2, you can now configure Openfire to make use of the certificate stores that are part of / managed by Microsoft Windows. Note that doing this currently allows for Openfire to make <a href="https://issues.igniterealtime.org/browse/OF-1878" rel="nofollow noopener">modifications</a> to these stores! Some might consider this a bug, while others think it?s a feature.</p>
<p>To configure Openfire to make use of the Windows keystores, define these properties:</p>
<ul>
<li>property name: <code>xmpp.socket.ssl.trustStoreType</code> value: <code>Windows-ROOT</code>
</li>
<li>property name: <code>xmpp.socket.ssl.identityStoreType</code> value: <code>Windows-MY</code>
</li>
<li>property name: <code>xmpp.socket.ssl.client.trustStoreType</code> value: <code>Windows-ROOT</code>
</li>
<li>property name: <code>xmpp.socket.ssl.client.identityStoreType</code> value: <code>Windows-MY</code>
</li>
</ul>
<p>As the feature is new, we?d love your feedback and suggestions on this!</p>
