<h1 id="electron-builder">electron-builder <a href="https://yarn.pm/electron-builder"><img alt="npm version" src="https://img.shields.io/npm/v/electron-builder.svg?label=latest"/></a> <a href="https://yarn.pm/electron-builder"><img alt="downloads per month" src="https://img.shields.io/npm/dm/electron-builder.svg"/></a> <a href="https://www.electron.build/donate"><img alt="donate" src="https://img.shields.io/badge/donate-donorbox-green.svg"/></a> <a href="https://electron-builder.zulipchat.com"><img alt="project chat" src="https://img.shields.io/badge/chat-on_zulip-brightgreen.svg"/></a><a class="headerlink" href="#electron-builder" title="Permanent link">¶</a></h1>
<p>A complete solution to package and build a ready for distribution Electron app for macOS, Windows and Linux with “auto update” support out of the box.</p>
<ul>
<li>NPM packages management:<ul>
<li><a href="https://electron.atom.io/docs/tutorial/using-native-node-modules/">Native application dependencies</a> compilation (including <a href="http://yarnpkg.com/">Yarn</a> support).</li>
<li>Development dependencies are never included. You don’t need to ignore them explicitly.</li>
<li><a href="/tutorials/two-package-structure">Two package.json structure</a> is supported, but you are not forced to use it even if you have native production dependencies.</li>
</ul>
</li>
<li><a href="/code-signing">Code Signing</a> on a CI server or development machine.</li>
<li><a href="/auto-update">Auto Update</a> ready application packaging.</li>
<li>Numerous target formats:<ul>
<li>All platforms: <code>7z</code>, <code>zip</code>, <code>tar.xz</code>, <code>tar.lz</code>, <code>tar.gz</code>, <code>tar.bz2</code>, <code>dir</code> (unpacked directory).</li>
<li><a href="/configuration/mac#MacConfiguration-target">macOS</a>: <code>dmg</code>, <code>pkg</code>, <code>mas</code>, <code>mas-dev</code>.</li>
<li><a href="/configuration/linux#LinuxConfiguration-target">Linux</a>: <a href="http://appimage.org">AppImage</a>, <a href="http://snapcraft.io">snap</a>, debian package (<code>deb</code>), <code>rpm</code>, <code>freebsd</code>, <code>pacman</code>, <code>p5p</code>, <code>apk</code>.</li>
<li><a href="/configuration/win#WindowsConfiguration-target">Windows</a>: <code>nsis</code> (Installer), <code>nsis-web</code> (Web installer), <code>portable</code> (portable app without installation), AppX (Windows Store), Squirrel.Windows.</li>
</ul>
</li>
<li><a href="/configuration/publish">Publishing artifacts</a> to GitHub Releases, Amazon S3, DigitalOcean Spaces and Bintray.</li>
<li>Advanced building:<ul>
<li>Pack in a distributable format <a href="#pack-only-in-a-distributable-format">already packaged app</a>.</li>
<li>Separate <a href="https://github.com/electron-userland/electron-builder/issues/1102#issuecomment-271845854">build steps</a>.</li>
<li>Build and publish in parallel, using hard links on CI server to reduce IO and disk space usage.</li>
<li><a href="https://github.com/electron/electron-compile">electron-compile</a> support (compile for release-time on the fly on build).</li>
</ul>
</li>
<li><a href="/multi-platform-build#docker">Docker</a> images to build Electron app for Linux or Windows on any platform.</li>
<li><a href="https://proton-native.js.org/">Proton Native</a> support.</li>
<li>Downloads all required tools files on demand automatically (e.g. to code sign windows application, to make AppX), no need to setup.</li>
</ul>

<h2 id="installation">Installation<a class="headerlink" href="#installation" title="Permanent link">¶</a></h2>
<p><a href="http://yarnpkg.com/">Yarn</a> is <a href="https://github.com/electron-userland/electron-builder/issues/1147#issuecomment-276284477">strongly</a> recommended instead of npm.</p>
<p><code>yarn add electron-builder --dev</code></p>

<h2 id="quick-setup-guide">Quick Setup Guide<a class="headerlink" href="#quick-setup-guide" title="Permanent link">¶</a></h2>
<p><a href="https://github.com/electron-userland/electron-webpack-quick-start">electron-webpack-quick-start</a> is a recommended way to create a new Electron application.</p>
<ol>
<li>
<p>Specify the standard fields in the application <code>package.json</code> — <a href="/configuration/configuration#Metadata-name">name</a>, <code>description</code>, <code>version</code> and <a href="https://docs.npmjs.com/files/package.json#people-fields-author-contributors">author</a>.</p>
</li>
<li>
<p>Specify the <a href="/configuration/configuration#configuration">build</a> configuration in the <code>package.json</code> as follows:
    </p><div class="highlight"><pre><span></span><span class="s2">"build"</span><span class="err">:</span> <span class="p">{</span>
  <span class="nt">"appId"</span><span class="p">:</span> <span class="s2">"your.id"</span><span class="p">,</span>
  <span class="nt">"mac"</span><span class="p">:</span> <span class="p">{</span>
    <span class="nt">"category"</span><span class="p">:</span> <span class="s2">"your.app.category.type"</span>
  <span class="p">}</span>
<span class="p">}</span>
</pre></div>
   See <a href="/configuration/configuration#configuration">all options</a>. Option <a href="/configuration/contents#files">files</a> to indicate which files should be packed in the final application, including the entry file, maybe required.<p></p>
</li>
<li>
<p>Add <a href="/icons">icons</a>.</p>
</li>
<li>
<p>Add the <a href="https://docs.npmjs.com/cli/run-script">scripts</a> key to the development <code>package.json</code>:
    </p><div class="highlight"><pre><span></span><span class="s2">"scripts"</span><span class="err">:</span> <span class="p">{</span>
  <span class="nt">"pack"</span><span class="p">:</span> <span class="s2">"electron-builder --dir"</span><span class="p">,</span>
  <span class="nt">"dist"</span><span class="p">:</span> <span class="s2">"electron-builder"</span>
<span class="p">}</span>
</pre></div>
    Then you can run <code>yarn dist</code> (to package in a distributable format (e.g. dmg, windows installer, deb package)) or <code>yarn pack</code> (only generates the package directory without really packaging it. This is useful for testing purposes).<p></p>
<p>To ensure your native dependencies are always matched electron version, simply add script <code>"postinstall": "electron-builder install-app-deps"</code> to your <code>package.json</code>.</p>
</li>
<li>
<p>If you have native addons of your own that are part of the application (not as a dependency), set <a href="/configuration/configuration#Configuration-nodeGypRebuild">nodeGypRebuild</a> to <code>true</code>.</p>
</li>
</ol>
<p>Please note that everything is packaged into an asar archive <a href="/configuration/configuration#Configuration-asar">by default</a>.</p>
<p>For an app that will be shipped to production, you should sign your application. See <a href="/code-signing#where-to-buy-code-signing-certificate">Where to buy code signing certificates</a>.</p>
<h2 id="programmatic-usage">Programmatic Usage<a class="headerlink" href="#programmatic-usage" title="Permanent link">¶</a></h2>
<p>See <code>node_modules/electron-builder/out/index.d.ts</code>. Typings for TypeScript is provided.</p>
<div class="highlight"><pre><span></span><span class="s2">"use strict"</span>

<span class="kr">const</span> <span class="nx">builder</span> <span class="o">=</span> <span class="nx">require</span><span class="p">(</span><span class="s2">"electron-builder"</span><span class="p">)</span>
<span class="kr">const</span> <span class="nx">Platform</span> <span class="o">=</span> <span class="nx">builder</span><span class="p">.</span><span class="nx">Platform</span>

<span class="c1">// Promise is returned</span>
<span class="nx">builder</span><span class="p">.</span><span class="nx">build</span><span class="p">({</span>
  <span class="nx">targets</span><span class="o">:</span> <span class="nx">Platform</span><span class="p">.</span><span class="nx">MAC</span><span class="p">.</span><span class="nx">createTarget</span><span class="p">(),</span>
  <span class="nx">config</span><span class="o">:</span> <span class="p">{</span>
   <span class="s2">"//"</span><span class="o">:</span> <span class="s2">"build options, see https://goo.gl/QQXmcV"</span>
  <span class="p">}</span>
<span class="p">})</span>
  <span class="p">.</span><span class="nx">then</span><span class="p">(()</span> <span class="p">=&gt;</span> <span class="p">{</span>
    <span class="c1">// handle result</span>
  <span class="p">})</span>
  <span class="p">.</span><span class="k">catch</span><span class="p">((</span><span class="nx">error</span><span class="p">)</span> <span class="p">=&gt;</span> <span class="p">{</span>
    <span class="c1">// handle error</span>
  <span class="p">})</span>
</pre></div>
<h2 id="pack-only-in-a-distributable-format">Pack Only in a Distributable Format<a class="headerlink" href="#pack-only-in-a-distributable-format" title="Permanent link">¶</a></h2>
<p>You can use electron-builder only to pack your electron app in a AppImage, Snaps, Debian package, NSIS, macOS installer component package (<code>pkg</code>) 
and other distributable formats.</p>
<div class="highlight"><pre><span></span>./node_modules/.bin/electron-builder --prepackaged &lt;packed dir&gt;
</pre></div>
<p><code>--projectDir</code> (the path to project directory) option also can be useful.</p>
<h2 id="debug">Debug<a class="headerlink" href="#debug" title="Permanent link">¶</a></h2>
<p>Set the <code>DEBUG</code> environment variable to debug what electron-builder is doing:
</p><div class="highlight"><pre><span></span><span class="nv">DEBUG</span><span class="o">=</span>electron-builder
</pre></div><p></p>
<p><code>FPM_DEBUG</code> env to add more details about building linux targets (except snap and appimage).</p>
<div class="admonition tip">
<p class="admonition-title">cmd</p>
<p>On <a href="https://github.com/visionmedia/debug#windows-command-prompt-notes">Windows</a> the environment variable is set using the set command.
</p><div class="highlight"><pre><span></span><span class="nb">set</span> <span class="nv">DEBUG</span><span class="o">=</span>electron-builder
</pre></div><p></p>
</div>
<div class="admonition tip">
<p class="admonition-title">PowerShell</p>
<p>PowerShell uses different syntax to set environment variables.
</p><div class="highlight"><pre><span></span><span class="nv">$env</span>:DEBUG<span class="o">=</span>electron-builder
</pre></div><p></p>
</div>
