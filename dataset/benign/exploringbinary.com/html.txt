<p>The binary fraction 0.101 <a href="https://www.exploringbinary.com/binary-converter/" title="Rick Regan's Decimal/Binary Converter">converts to</a> the decimal fraction 0.625; the binary fraction 0.1010001 converts to the decimal fraction 0.6328125; the binary fraction 0.00111011011 converts to the decimal fraction 0.23193359375. In each of those examples, the binary fraction converts to a decimal fraction — that is, a terminating decimal representation — that has the same number of digits as the binary fraction has bits.</p>
<p>One digit per bit? We know that’s <a href="https://www.exploringbinary.com/number-of-decimal-digits-in-a-binary-integer/" title="Read Rick Regan's Article “Number of Decimal Digits In a Binary Integer”">not true for binary integers</a>. <p>This is the reason why you get all those “extra” digits when you print the full decimal value of an IEEE binary floating-point fraction, and why <a href="https://www.exploringbinary.com/how-glibc-strtod-works/" title="Read Rick Regan's Article “How GLIBC’s strtod() Works”">glibc strtod()</a> and <a href="https://www.exploringbinary.com/visual-c-plus-plus-strtod-still-broken/" title="Read Rick Regan's Article “Visual C++ strtod(): Still Broken”">Visual C++ strtod()</a> were once broken.</p>

<h2 class="entry-title"><a href="https://www.exploringbinary.com/the-shortest-decimal-string-that-round-trips-may-not-be-the-nearest/" rel="bookmark">The Shortest Decimal String That Round-Trips May Not Be The Nearest</a></h2> <div class="fixed_byline">By <a href="https://www.exploringbinary.com/about/">Rick Regan</a>  April 28th, 2016</div>
</header><!-- .entry-header -->
<div class="entry-content">
<p>Any double-precision floating-point number can be identified with at most 17 significant decimal digits. This means that if you convert a floating-point number to a decimal string, round it (to nearest) to 17 digits, and then convert that back to floating-point, you will recover the original floating-point number. In other words, the conversion will <em>round-trip</em>.</p>
<p>Sometimes <a href="https://www.exploringbinary.com/the-shortest-decimal-string-that-round-trips-examples/" title="Read Rick Regan's article “The Shortest Decimal String That Round-Trips: Examples”">(many) fewer than 17 digits will serve to round-trip</a>; it is often desirable to find the shortest such string. Some programming languages generate shortest decimal strings, but many do not.<sup>1</sup> If your language does not, you can attempt this yourself using brute force, by rounding a floating-point number to increasing length decimal strings and checking each time whether conversion of the string round-trips. For double-precision, you’d start by rounding to 15 digits, then if necessary to 16 digits, and then finally, if necessary, to 17 digits.</p>
<p>There is an interesting anomaly in this process though, one that I recently learned about from Mark Dickinson on <a href="https://stackoverflow.com/a/35708911/100914" title="Mark Dickinson's answer on stackoverflow.com">stackoverflow.com</a>: in rare cases, it’s possible to overlook the shortest decimal string that round-trips. Mark described the problem in the context of single-precision binary floating-point, but it applies to double-precision binary floating-point as well — or any precision binary floating-point for that matter. I will look at this anomaly in the context of double-precision floating-point, and give a detailed analysis of its cause.</p>

But instead of 100, I plugged in a floating-point number; I got the expected “unexpected” results.</p>
