<section class="g-section bg-light" id="how-terraform-works">
<div class="g-container">
<div class="intro">
<h2>
                    How Terraform Works
                </h2>
</div>
<div class="g-tabbed-content g-text-asset" id="how-terraform-works-tabs">
<ul class="tab-list">
<li class="active" id="tab-cloud"><a aria-controls="tab-cloud" aria-selected="true" href="#cloud">Cloud</a></li>
<li id="tab-cli"><a aria-controls="tab-cloud" aria-selected="false" href="#cli">CLI</a></li>
</ul>
<div aria-hidden="false" aria-labelledby="tab-cloud" class="tab-panel active" data-hashi-tab="tab-cloud" id="tab-panel-cloud">
<div class="tab-content">
<picture>
<source srcset="
                                    /assets/images/terraform-overview/cloud-howitworks-1x-c9ceba97.png 300w,
                                    /assets/images/terraform-overview/cloud-howitworks-2x-c1f1ae25.png 704w,
                                    /assets/images/terraform-overview/cloud-howitworks-2a247cdb.png 1256w" type="image/png"/>
<img alt="Terraform Cloud - How It Works Diagram" src="/assets/images/terraform-overview/cloud-howitworks-2x-c1f1ae25.png"/>
</picture>
</div>
<div class="tab-content">
<h4>Terraform Cloud</h4>
<h5>Write Infrastructure as Code</h5>
<p>Terraform users define infrastructure in a simple, human-readable configuration language
                                called HCL
                                (HashiCorp
                                Configuration Language). Users can write unique HCL configuration files or borrow
                                existing templates
                                from
                                the public
                                module registry.</p>
<h5>Manage Configuration Files in VCS</h5>
<p>Most users will store their configuration files in a version control system (VCS) repository and
                                connect that repository
                                to a
                                Terraform
                                Cloud workspace. With that connection in place, users can borrow best practices from software
                                engineering to
                                version
                                and
                                iterate on infrastructure as code, using VCS and Terraform Cloud as a delivery pipeline
                                for
                                infrastructure.
                            </p>
<h5>Automate Provisioning</h5>
<p>When you push changes to a connected VCS repository, Terraform Cloud will automatically trigger a plan
                                in any workspace connected to that repository.
                                This plan can be
                                reviewed for
                                safety and accuracy in the Terraform UI, then it can be applied to provision the
                                specified
                                infrastructure.
                            </p>
</div>
</div>
<div aria-hidden="true" aria-labelledby="tab-cli" class="tab-panel" data-hashi-tab="tab-cli" id="tab-panel-cli">
<div class="tab-content">
<picture>
<source srcset="
                                      /assets/images/terraform-overview/cli-howitworks-1x-43424a9b.png 300w,
                                      /assets/images/terraform-overview/cli-howitworks-2x-0b1a3eb0.png 704w,
                                      /assets/images/terraform-overview/cli-howitworks-1581d13e.png 1256w" type="image/png"/>
<img alt="Terraform CLI - How It Works Diagram" src="/assets/images/terraform-overview/cli-howitworks-2x-0b1a3eb0.png"/>
</picture>
</div>
<div class="tab-content">
<h4>CLI</h4>
<p>Terraform allows infrastructure to be expressed as code in a simple, human readable
                                language called HCL (HashiCorp
                                Configuration Language). Terraform CLI reads configuration files and provides an
                                execution plan of changes, which can
                                be reviewed for safety and then applied and provisioned. Extensible providers allow
                                Terraform to manage a broad range
                                of resources, including hardware, IaaS, PaaS, and SaaS services.</p>
<div class="check">
<ul>
<li>Infrastructure as Code</li>
<li>200+ available providers</li>
<li>Provision any infrastructure</li>
</ul>
</div>
