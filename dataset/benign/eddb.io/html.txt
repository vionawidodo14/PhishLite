<div class="featured">EDDB has been updated for 3.3 - Elite Dangerous: Beyond - Chapter Four! <small>05-01-19</small></div>
<p>I'm pleased to announce that EDDB has (finally) been updated for the new 3.3 update. Since a lot of internal stuff changed, errors could happen. Please don't hesitate to contact me on Discord if you experience any unexpected behavior.</p>
<ul class="feature-sub-list">
<li>
                        Complete rewrite of the EDDN parser. This allows better error detection and cleaner data import. It took far longer than I anticipated. I'm very happy with the current solution though, so it was worth it.
                    </li>
<li>
                        Adding all new commodities, ships and ship modules.
                    </li>
<li>
                        Adding all new allegiance and government types.
                    </li>
<li>
                        Adapting EDDB to the new faction behavior: Factions now have multiple states which get inherited by their controlled systems and stations.
                    </li>
<li>
                        Many little fixes I forgot to keep track of
                    </li>
<li>
                        For now the EDDN body parsing has been disabled. This should not have a big impact, since a lot of bodies have been imported already. I expect to get the parsing back within a week.
                    </li>
</ul>
<p><strong>API Update!</strong> The nightly dump schema has been updated. Check the <a href="/api">API page</a> for more information.</p>

<div class="featured">Minor Faction enhancement! <small>03-10-16</small></div>
<p>With the upcoming release of Elite: Dangerous 2.2 and the introduction of the journal (find out more about it
    <span class="semi-strong"><a href="https://forums.frontier.co.uk/showthread.php/275151-Commanders-log-manual-and-data-sample">here</a></span>,
    <span class="semi-strong"><a href="https://github.com/jamesremuscat/EDDN/pull/49">here</a></span>,
    <span class="semi-strong"><a href="https://github.com/jamesremuscat/EDDN/pull/48">here</a></span>,
    <span class="semi-strong"><a href="https://www.reddit.com/r/EliteDangerous/comments/546ed1/edmc_and_eddn_have_been_adjusted_to_send_and/">here</a></span> and
    <span class="semi-strong"><a href="https://ross.eddb.io/eddn/log?onlyError=0&amp;onlyWarning=0&amp;parsing_result=221">here</a></span>) the 3rd party developer community will have an awesome opportunity
    to programmatically know what's going on in the game. In practice this means that with <span class="semi-strong"><a href="https://github.com/Marginal/EDMarketConnector/wiki">EDMC</a></span>
        (or another application supporting the journal and EDDN) every player will be able to <span class="semi-strong">update more data on EDDB automatically</span> without
    using <span class="semi-strong"><a href="https://ross.eddb.io/">ROSS</a></span>.
    This includes body information on detailed scan, black market prices on illegal commodity sale, or faction information on system arrival or station docking.
    This is an opportunity since only now we are able to keep track of factions and their state and system/station presence throughout the universe. And of course I had to take that opportunity and enhance EDDB.
</p>
<p>Overall changes on EDDB and ROSS</p><ul>
<li>Factions are a seperate entity now and can be updated on <span class="semi-strong"><a href="https://ross.eddb.io/faction">ROSS</a></span>.</li>
<li>Allegiance, government and state of a system or a station are now being auto-updated by specifically setting the controlling faction and its state at a system. All other systems and stations which the faction control, inherit these too.</li>
<li>On EDDB factions can be searched with the <span class="semi-strong"><a href="/faction/index">Minor Faction Search &amp; Finder</a></span>. If you come up with another filter that could be useful for you, drop me a message on <span class="semi-strong"><a href="https://discord.gg/0uwCh6R62aQ0eeAX">Discord</a></span> (@themroc).</li>
<li>The <span class="semi-strong"><a href="/system">System Finder</a></span> and <span class="semi-strong"><a href="/station">Station Finder</a></span> have been adjusted to filter your result by a specific faction.</li>
</ul>
<p>Wanna know more about the internals? <strong><a href="#" id="factionChangesReadMoreLink">Read more here!</a></strong></p>
<div id="factionChangesReadMoreBlock" style="display: none">
<p>The way factions work on EDDB has been reworked from scratch. Before this update, it worked like this:</p>
<ul>
<li>The <code>system</code> and the <code>station</code> tables each had a string property <code>faction</code> which could be edited freely.</li>
<li>The <code>state</code>, <code>allegiance</code> and <code>government</code> had to be set indivdually for each <code>system</code> and <code>station</code>.</li>
<li>There was no interconnection.</li>
</ul>
<p>With this update almost everything has changed:</p>
<ul>
<li>The <code>system</code> and <code>station</code> tables still have individual <code>allegiance</code> <code>government</code> and <code>state</code> properties.
            Those can not be updated manually and inherit their values from the <code>controlling faction</code></li>
<li>There is an individual <code>faction</code> table now. It holds <code>home system</code>, <code>government</code>, <code>allegiance</code> and if it's a <code>player faction</code>.
            You can browse the list and create new factions on the designated <span class="semi-strong"><a href="https://ross.eddb.io/faction">ROSS overview page</a></span>.</li>
<li>The <code>faction</code> table also contains a <code>global faction state</code> property which is read only and gets updated automatically.</li>
<li>The <code>system</code> and <code>station</code> tables both have a <code>controlling faction</code> property now.</li>
<li>The <code>system</code> now accumulates multiple instances of <code>faction presence</code>, which save the <code>influence</code> and the system specific <code>state</code> of every <code>faction</code> present at the system.</li>
<li>Changing the specific <code>faction system state</code> of a <code>faction</code> in a <code>system</code>:
            <ul>
<li>If the <code>faction system state</code> is a <code>conflict state</code> (<code>war</code>, <code>civil war</code> or <code>election</code>), only the <code>global faction state</code> inherits that.
                    Every other <code>faction system state</code> (in every other <code>system</code> the <code>faction</code> is present) falls back to <code>none</code>.</li>
<li>For every other <code>state</code>, every <code>faction system state</code> in every other <code>system</code> inherits the <code>global faction state</code> value as well.</li>
<li>If a <code>faction</code> controls a <code>system</code> or a <code>station</code>, the <code>local state</code> gets updated from the <code>faction system state</code> </li>
</ul>
</li>
<li>Changing the <code>controlling faction</code> of a <code>system</code> or a <code>station</code>:
            <ul>
<li>The <code>allegiance</code> and <code>government</code> of the <code>system</code> are changed to the <code>faction</code> values.</li>
<li>The <code>system state</code> is changed to the <code>system faction state</code> value.</li>
</ul>
</li>
</ul>
<p>So much about the internals. The problem (yes, of course, we got one...): The whole faction data quality on EDDB is utterly bad. It was just not possible to keep faction and state information up 2 date.
        Right now the <code>system state</code> and <code>station state</code> are not in sync with the <code>system faction state</code> of the <code>controlling faction</code>. Same goes for <code>allegiance</code> and <code>government</code>.
        I simply don't know what's more up2date. I decided to keep those untouched and only added the factions to the system without the implications described earlier. Only after the first change on ROSS or via EDDN will stuff be updated.
        I hope that this strategy will lead to the least errors. And in time, everything will get in order.
    </p>
</div>
<p>Enjoy o7</p>

<div class="featured"><strong>Material distribution!</strong> <small>05-09-16</small></div>
<p>The official introduction of the detailed distribution of materials on bodies made the logging almost obsolete.</p>
<ul>
<li>The place to input material data is <span class="semi-strong"><a href="https://ross.eddb.io/">ROSS</a></span> now. Below the ring input area, a material input area has been established. It is now possible to set specific distribution based material information for every body.</li>
<li>The material logger history has been purged. Instead you can find all changes on the <span class="semi-strong"><a href="https://ross.eddb.io/history">Database Change History</a></span> page on ROSS.</li>
<li>And of course the <span class="semi-strong"><a href="/body">Bodies - Search &amp; Find</a></span> page has been pimped as well! For every material that is searched in the finder, a seperate sortable column with the distribution value is added to the result list. This will make it easy to find the right body for your demands!</li>
<li>Unfortunately, with this update it is not possible to add material data to rings anymore, only bodies and belts are supported now. This might change at a later point though.</li>
</ul>
<p>Enjoy o7</p>
<hr/>
<div class="featured"><strong>EDDB proudly presents the introduction of Bodies!</strong> <small>22-06-16</small></div>
<p>Over the past months I was working on the goal to make bodies of ED a part of EDDB too.
                    It had to be complete in terms of data information. And it had to offer the search &amp; find experience like
                    the <span class="semi-strong"><a href="/system">Systems</a></span> or
                    <span class="semi-strong"><a href="/station">Stations</a></span> <span class="semi-strong">Finder</span>.
                    I believe that goal has been achieved.
                </p>
<ul class="feature-sub-list">
<li>
                        As usual, <span class="semi-strong"><a href="https://ross.eddb.io/">ROSS</a></span> acts as the backend and registered users are
                        able to edit every single body detail.
                        You can start on the <span class="semi-strong"><a href="https://ross.eddb.io/body/index">Body Overview</a></span>.
                    </li>
<li>
                        That said, EDDB is able to hold information for every kind of body in the ED galaxy.
                        This includes (compact) stars, planets, belts and rings. Every type got its own data set.
                        What you see on EDDB can be updated on ROSS.
                    </li>
<li>
<span class="semi-strong">Element Materials:</span> EDDB offers functionality for logging and finding materials.
                        With the <span class="semi-strong"><a href="/body/element-material-logger">Material Logger</a></span> you can
                        very easily tell EDDB what you found where (you need to be logged in). And with the
                        <span class="semi-strong"><a href="/body">Body Finder</a></span> you can set filters to find bodies yielding materials.
                    </li>
<li>
<span class="semi-strong">Resource Extraction Sites:</span> EDDB has records of rings and belts (again, add them on ROSS).
                        With the <span class="semi-strong"><a href="/body">Body Finder</a></span> you can find
                        the <span class="semi-strong">Pristine</span> and <span class="semi-strong">Metal Rich</span> site near you!
                    </li>
<li>
<span class="semi-strong">Statistics:</span> The <span class="semi-strong"><a href="/body">Body Search &amp; Finder</a></span>
                        gives you unlimited filter possibilities. Additionally you can select any body property available as extra result column and sort by it.
                        With this it's easy to find extreme bodies and their follow ups easily.
                    </li>
</ul>
<p>
                    A big thanks goes to <span class="semi-strong">CMDR Ian Baristan</span>.
                    Only with his help I was able to offer the huge amount of body images. The goal was never to get a 100% exact image system,
                    but to rather find default images that match the body roughly. Rings are not being visualized yet, but I'm sure I will find a way for this soon.
                </p>
<p>
                    With the great help of <span class="semi-strong">CMDR Wolzan</span>, the author of
                    <span class="semi-strong"><a href="http://www.elitegalaxyonline.com/">Elite Galaxy Online</a></span>, EDDB can start with more than 5000 bodies.
                    He supplied very high quality data from his site. Last but not least, thanks to <span class="semi-strong">CMDR Nexolek</span> for the
                    great inspiration and especially his element material base data.
                </p>
<p>I hope you enjoy the new features. If you feel like something's missing, feel free to contact me. You can find me in the <strong><a href="https://www.quakenet.org/">QuakeNet</a></strong> IRC
                    channel <span class="semi-strong">#eddb</span> (<strong><a href="https://kiwiirc.com/client/irc.quakenet.org/eddb">Web Client</a></strong>) or on the <strong><a href="http://edcd.github.io/">EDCD</a></strong>
<strong><a href="https://discord.gg/0uwCh6R62aQ0eeAX">Discord Server</a></strong>.</p>
<p><span class="semi-strong">What's next?</span> My next step will be the nightly JSON dump for bodies.
                    Also, I wanna look into a way to import <span class="semi-strong">Captains Log</span> bodies. But first I need a little break :)</p>
